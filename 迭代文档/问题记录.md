## 一、移植与依赖

### 1. GitHub 直连/ghproxy 超时下载失败  `发生: 2026-09-14` `解决: 2026-09-14`

**现象**：从 GitHub 下载 translate-book 仓库 tarball，直连和 `ghproxy` 镜像均超时（中国网络环境）。

**根因**：GitHub 大文件在国内网络不稳定，单一镜像单点失败。

**解决**：写多镜像脚本 `/root/scripts/download_tb.sh` 依次尝试（github.com → ghproxy → ghfast.top），`ghfast.top` 成功下载 11.8MB。

**改动文件**：无（下载脚本）

---

### 2. root 下 PDF 导出崩溃（Qt WebEngine sandbox）  `发生: 2026-09-14` `解决: 2026-09-14`

**现象**：`merge_and_build.py` 生成 PDF 失败，其他格式（HTML/DOCX/EPUB）正常。

**根因**：以 root 身份运行 Qt WebEngine（Calibre ebook-convert 底层）触发 Chromium sandbox 崩溃。

**解决**：`calibre_html_publish.py` 顶部加 `os.environ.setdefault("QTWEBENGINE_DISABLE_SANDBOX", "1")`，永久修复（后续任何方式运行都无需外部环境变量）。

**改动文件**：`book/scripts/calibre_html_publish.py`

---

### 3. 内联 `python3 -c` 挂起  `发生: 持续` `解决: 持续规避`

**现象**：`python3 -c "..."` 在服务器上无响应挂起。

**根因**：Docker 容器（nikolaik/python-nodejs）内的 Python 交互式/内联执行异常。

**解决**：一律写脚本文件再执行，不用内联 `python3 -c`。

**改动文件**：无（操作习惯）

## 二、部署与网络

### 4. Cloudflare Origin Rule 配置导致 521（两次）  `发生: 2026-09-14` `解决: 2026-09-14`

**现象**：trs.andrew-li.top 公网访问 HTTPS 521（源站不可达），scan 正常。

**根因（两次不同）**：
1. 首次：CF 无法猜源站端口，默认回源 443/80 无监听 → 521
2. 二次：Origin Rule 匹配字段误用 **「URI 完整」**——URI 匹配的是 URL 路径（`/`），**永不匹配域名** → 规则不生效仍 521

**解决**：
1. Origin Rule 端口重写固定 8080（服务器唯一 HTTP 入口 Caddy）
2. 匹配字段改为 **Hostname**（Host 头），Host 头保持原样让 Caddy 按域名分流

**改动文件**：Cloudflare 控制台（Origin Rules），非代码

### 5. Caddy admin 端口从 2019 变 2020 导致 reload 失败  `发生: 2026-09-15` `解决: 2026-09-15`

**现象**：`caddy reload` 报 admin 端点连接被拒。

**根因**：Caddyfile 里有全局 `{admin 127.0.0.1:2020}` 块，reload 走 admin API 连 2020 被拒。

**解决**：去掉 admin 块恢复默认 2019；reload 通过 admin API `POST /load` 到 2019 加载新配置。

**改动文件**：`/root/caddy/Caddyfile`

## 三、翻译流水线

### 6. merge 校验把空尾 chunk 误判为失败  `发生: 2026-09-15~16` `解决: 2026-09-16`

**现象**：《Bioinformatics Data Skills》200/200 块全部译完，job 却显示 failed，卡在 merge。

**根因**：`chunk0200` 是 convert 生成的 **0 字节合法空块**（PDF 末尾空白页），子代理译文同样为空，merge 校验把空输出当成「该块未翻译」拒绝合并。

**解决**：`manifest.py` + `merge_and_build.py` 加 `source_empty` 补丁（容忍源为空的块）→ 重跑 merge exit 0 → 状态修正 done。

**教训**：**空 chunk 是合法产物**，不是失败；merge 校验必须区分「源空」和「源非空但输出空」。

**改动文件**：`book/scripts/manifest.py`, `book/scripts/merge_and_build.py`

---

### 7. `merge_and_build --cleanup` 删除对照依赖文件  `发生: 2026-09-15` `解决: 2026-09-15`

**现象**：merge 后查看器的「对照阅读」tab 失效。

**根因**：`--cleanup` 会删除 `chunk*.md` 和 `output_chunk*.md`，而前端对照 tab 依赖这些文件。

**解决**：merge watcher 调用**禁用 cleanup**；cleanup 留给用户手动定期执行。

**改动文件**：`web/main.py`（watcher 调用参数）

---

### 8. pick 死循环（output 已存在未记录）  `发生: 2026-09-15` `解决: 2026-09-15`

**现象**：cron 翻译批次可能死循环重复 pick 同一块。

**根因**：output_chunk 文件已存在（如上次 3 分钟窗口中断前已写完），但 run_state 未记录 → 下一轮 pick 仍认为未译 → 重译。

**解决**：`consumer.py pick` 时自动 `record_only`（检测到 output 已存在即补记录），绝不重复翻译。

**改动文件**：`web/consumer.py`

---

### 9. 3 分钟窗口内单块翻译超时  `发生: 2026-09-15` `解决: 2026-09-15`

**现象**：delegate_task 3 块并行最坏 268s > cron 3 分钟硬中断，任务可能被掐断。

**根因**：Hermes cron 单次会话 3 分钟硬限制，长 chunk 翻译无法在窗口内完成。

**解决**：**断点续译**——output 落盘后即使中断，下轮 pick 自动 record_only 续译；cron prompt 明确「超时安全：绝不重复翻译」。

**改动文件**：`web/consumer.py`, cron prompt

## 七、D 方案（脚本直连 API）· 2026-09-17

### 17. `consumer.finish()` 全 done 时不写 merge_request.json，合并永不触发  `发生: 2026-09-17` `解决: 2026-09-17`

**现象**：D 方案翻译完 abtest 测试书 37 块，job 状态停在 `merging`，但 Web watcher 一直不执行合并，成品不生成。

**根因**：`consumer.finish()` 在全部块译完时只把 job 置 `status=merging`，**不写 `merge_request.json`**；而 Web 的 merge watcher（`web/main.py _merge_one_round`）要求 **`status==merging` AND `merge_request.json` 存在** 才执行构建。缺后者则永不触发。

**解决**：`translate_direct.py` 的 `process_task` 在 `fin()` 返回 `all_done` 后，显式再调 `consumer.request_merge(job_id, title)` 写 merge_request.json + 置 merging。已卡住的旧任务手动补 `jobs/<id>/merge_request.json` 即恢复。

**改动文件**：`web/translate_direct.py`

### 18. 直连 API 在插图密集 chunk 丢整块图片引用，merge 校验失败  `发生: 2026-09-17` `解决: 2026-09-17`

**现象**：abtest 测试书合并报 `ERROR: output_chunk0003.md image references diverge from chunk0003.md`，missing `images/000002.png`、`images/000036.png`，任务 failed。

**根因**：D 直连 amd API 翻译时，模型在插图密集的长 chunk（如 chunk0003）会**把整块 `![](images/xxx)` 图片引用全部丢弃**。merge_and_build 的 image validation 严格比对源/输出图片引用，缺图即拒绝合并。

**解决**：新增 `fix_images.py` 后处理——每块译完比对源 chunk 和 output 的图片引用，缺失的按源原样补回（追加到 output 末尾）。已集成进 `translate_direct.py`（`translate_one` 自动跑），实测补回 2 图后 merge 成功。cron（delegate_task）方案因子代理有 read_file 约束不丢图，此坑为 D 直连独有。

**改动文件**：`web/fix_images.py`（新增）、`web/translate_direct.py`

**教训**：**prompt 约束（"保留图片引用"）对直连 API 不可靠**——长块/插图密集块模型会丢图。必须加确定性后处理兜底（比对补回），不能只靠 prompt。

### 19. 直连 API 幻觉生成多余图片引用（extra 图）  `发生: 2026-09-17` `解决: 2026-09-17`

**现象**：Bioinformatics 书 merge 报 `output_chunk0024.md image references diverge`，**extra** `images/000070.jpg`（源 chunk0024 根本没有这张图）。

**根因**：模型翻译时**幻觉生成**图片引用 `[]![Image 48](images/000070.jpg)`（畸形语法 + 源里不存在的图）。image validation 双向校验（missing 和 extra 都拒绝）。

**解决**：`fix_images.py` 增强——`remove_extra_imgs()` 删除 output 里源不存在的图片引用行（整行删），先删多余再补缺失。全量脚本 `/tmp/fix_all_images.py <temp_dir>` 扫描全书修复后重跑 merge。

**改动文件**：`web/fix_images.py`

**教训**：图片校验是**双向**的（缺图失败、多图也失败），修复脚本必须同时处理。

### 20. EPUB 生成 SplitError（大代码块无分割点）  `发生: 2026-09-17` `解决: 2026-09-17`

**现象**：Bioinformatics 书 DOCX/PDF 生成成功，EPUB 失败：`SplitError: Could not find reasonable point at which to split`，sub-tree 260KB。

**根因**：书里有个 **163KB 无标题的连续代码块**（bwa/samtools/GATK 命令区），Calibre EPUB 分割（flow-size 默认 260KB）在无 `<h1>/<h2>` 的可分割点时报 SplitError。

**解决**：EPUB 生成加 `--flow-size 500`（不强制分割超大块）→ 生成成功（20.8MB，仅"无 TOC 用默认 TOC"的次要影响）。已固化进 `calibre_html_publish.py`。

**改动文件**：`book/scripts/calibre_html_publish.py`

---

### 21. amd 通道每日 $1 限额触顶（fallback 到 ark）  `发生: 2026-09-17` `解决: 2026-09-17`

**现象**：D 方案翻译到 chunk0122 时持续 429：`Daily usage limit exceeded: maximum $1 per period for this OneClick user`，当天剩余全部失败。

**根因**：amd 免费档按金额计费，**每日 $1 硬限额**（约 120 块/天），触顶后当天不可恢复。

**解决**：`translate_direct.py` 支持 **PROVIDERS 多通道 fallback**——amd 触顶（429 Daily usage/rate_limit_exceeded）或鉴权失败（401/403）自动切 **ark（火山方舟 arkapikey）**，日志记 `🔄 通道切换: amd → ark`。实测 ark 38s 翻完剩余块。

**改动文件**：`web/translate_direct.py`

**教训**：免费通道的限额按金额算且会**当天触顶**——生产链路必须配 fallback 通道，不能单通道硬撑。
