## 二、成品分发（E 方案 · R2）

```
浏览器 ──点下载──► GET /api/download/{name}/book.pdf      （管理员凭据；游客被 403）
                      │
                      ├─ R2 已配置 → 返回预签名 URL
                      │     └─► window.location.href 顶级导航 ──► R2 桶 books/{书名}/book.pdf
                      │           （15 分钟时效，attachment 保原名，浏览器直写磁盘）
                      └─ R2 不可用 → {url:null, fallback:"/api/books/.../download/..."}
                            └─► 前端回退 fetch+Blob → FileResponse 本地成品

本地 work/{书名}_temp/book.{pdf,docx,epub}  ══ r2_sync.py 每 15 分钟幂等上传 ══► R2
   ▲ 本地必须保留（_status()/_file_summary() 依赖）——R2 是分发通道，不是备份
```

## 三、数据流（一次完整翻译）

```
上传(PDF/DOCX/EPUB ≤100MB)
  → POST /api/upload → job {pending}
  → convert 后台线程 → {converting}
  → 生成 chunk0001..N + manifest → {ready}
  → translate-direct.service（D 方案主引擎）持续轮询：
      consumer.py pick → 3 块
      直连通道 API 翻译（PROVIDERS: amd → ark；reasoning_effort=none + 术语表 + 邻居上下文 + fix_images 补图）
      ⚠️ 两跳 2026-09-19 起均不可用（amd 对话模型下线 / ark 周配额耗尽），见问题记录 #29
      output_chunk{i}.md 落盘
      consumer.py finish → record + 进度
  → 全书完成 → consumer.py request-merge → {merging}
  → Web merge watcher（60s）检测 → merge_and_build.py
  → 5 格式成品（pdf/docx/epub/html/output.md）→ {done}
  （D 失效时 cron ab9ef9653179 每 3 分钟接管，delegate_task 3 块，逻辑同上）
```

## 三、任务状态机

```
pending ──convert──► converting ──convert成功──► ready
                       │                            │
                       └──失败──► failed             │ cancel ─► cancelled
                                                    ▼
                                              translating（D 主引擎 / cron 兜底译块）
                                                    │ 全部完成
                                                    ▼
                                              merging（watcher）
                                                    │ 成功/失败
                                                    ▼
                                              done / failed
```

任意状态可被 trash（进行中 409 保护）→ 回收站 → restore。

## 六、关键机制

### 断点续译
output_chunk{i}.md 落盘即「已翻译」事实 → 中断后 pick 自动 record_only → 绝不重译。

### 术语表重译
PUT glossary → 内容哈希变化 → affected_chunks 重置 ready → cron 下轮接手。

### merge 防坑
- watcher 不用 `--cleanup`（对照 tab 依赖 chunk 文件）
- source_empty 补丁（空尾 chunk 合法）

### 鉴权分层（游客 / 管理员）
- `AuthMiddleware` 是所有请求的第一道关：无 `Authorization` = 游客（只读白名单），凭据有效 = 管理员，**凭据无效 = 401 不降级**
- **哈希来源**：服务器本地凭据文件 `/root/.translate-web-cred` 的 `bcrypt` 行（`auth.py:load_admin_cred`），**代码里没有任何哈希**；读不到 → 管理员登录 fail closed（游客不受影响）
- 白名单集中在 `guest_rules.py`（读端点 + file 扩展名），改权限不用动反代配置
- **Caddy 只转发不做认证**——反代层做认证会把游客一起挡掉，且前端拿不到可编程响应
- 前端凭据存 `localStorage`，**必须显式 `fetch` 带 `Authorization` 头**；下载/导出走 `fetch + Blob`（`window.location`/`<a href>` 不带凭据）

### 进度解析
`books.py:_progress()` 把状态串解析为 `{done,total,pct,active}`；前端 `progOf()` 保留同款兜底解析，**前后端部署顺序不构成硬依赖**（详见经验总结 #17）。

### 成品分发（R2）
- 成品（pdf/docx/epub）走 R2 预签名 URL，前端 `window.location.href` 顶级导航直下——**不占 VPS 出网流量、不进浏览器内存**
- 端点 `/api/download/{name}/{path}`：R2 不可用/未配置 → 返回 `fallback` 指回本地 `/api/books/{name}/download/{path}`，前端自动回退
- `r2_sync.py` 每 15 分钟扫描 `work/*_temp` 幂等同步（同尺寸跳过），零侵入不改 merge 流程；**timer 已于 2026-09-19 19:40 `enable --now`**（首轮全量归档完成后才启用，避免刷失败日志），首发即触发一次（`OnBootSec=3min` 早已过期 + `Persistent=true`，属预期）
- `r2_sync.py` **上传必须单分片串行**：本机出网 ~1Mbps，boto3 默认 `max_concurrency=10` → 8MB 分片超时断连，**>8MB 的文件必然失败**；固定 `max_concurrency=1` + `use_threads=False` + `read_timeout=600`（问题 #31）
- 对账工具 `/root/scripts/r2_reconcile.py`：`list_objects_v2` 拉全桶对象比尺寸，输出 `OK/MISS/SIZE`；**`--dry-run` 只枚举本地待传文件、不查远端**，不能用来判断归档完成（问题 #32）
- **Web 可见性（v5.7）**：`/api/books` 附带 `storage` 汇总与每本书 `r2{object_count,expected,missing,mismatch,extra,synced}`；后端 `r2.snapshot()` **一次列举 `books/` 前缀分组比对** + **30s 缓存** + **短超时 fast 客户端**（connect 5s/read 15s/不重试），失败静默降级（`configured:false` / `available:false` → 前端显示 `R2 —` / `R2 ?`）；书卡徽章、书库汇总条、详情页存储行均由此驱动

### 存储页（S2）· 归档守护（S3）· 下载源可见（S4）

**S2 存储页**（`/api/storage`，管理员专享）

- **逐书三列对照**：本地成品（数/体积）｜ R2 对象（数/体积）｜ 差异（缺 / 尺寸不符 / 多余，逐项列名）
- **孤儿对象**：R2 上有、本地不该有的对象，两类 —— `ghost_book`（整本书本地已不存在，删书/清空回收站后遗留）与 `extra`（书还在但该文件本地已无）；侧栏「▦ 存储 · STORAGE」入口（仅管理员可见）
- **容量汇总**：本地工作区实际占用（`rglob` 累加，**60s 缓存**——遍历 400MB 目录不宜每请求都做）｜ 本地磁盘 used/total/pct ｜ R2 对象数与字节数 / 免费额度 10GB 占比条
- **一键清理孤儿**：`POST /api/storage/gc`，安全设计见经验总结 #28（**删前重拉远端复核 + 本地存在同名成品一律拒绝 + 读不到远端就整体放弃 + 单次上限 500**）
- `refresh=1` 绕过 30s 快照缓存（页内「↻ 刷新」按钮走这个）

**S3 归档守护 + S6 容量采样**（`web/r2_alert.py` + Hermes `no_agent` cron，每 30 分钟；零新增 cron/脚本）

- **5 个监护条件**（可同时命中，**合并成一条告警**，表头「N 项异常」+ 各块 `————` 分隔）：
  | 条件 | 触发 | 阈值 |
  |---|---|---|
  | `diff` | 本地成品 vs R2 对象不一致（缺 / 尺寸不符 / 多余）| 差异项 > 0 |
  | `unreachable` | R2 元数据读不到（凭证 / 网络 / bucket）| — |
  | `disk` | 服务器磁盘使用率 | **> 85%**（机器级：盘满会连带 trs/scan 全挂）|
  | `quota` | R2 用量占免费额度 | **> 80%**（10GB 额度）|
  | `hist` | 容量采样断更（采样链自我体检）| **> 36h** 无新采样 |
- **状态机**：差异/异常持续 **≥30 分钟**才告警（观察期去抖）；**签名由全部子条件计算** → 条件集合一变即**重开观察期**；**同签名 6 小时内只提醒一次**；**恢复正常发一条「已恢复」**；**未配置凭证静默**（功能未启用≠故障）；**脚本自身崩溃也告警**；**正常时 stdout 为空 → cron 零投递**
- 状态文件 `work/.r2_alert_state.json`；自检 `--selftest diff,disk,quota,hist --age N`、`--json`、`--no-state`、`--no-sample`、`--state/--history PATH`（测试隔离用）
- **每日容量采样**（S6 精简 B：与守护**同进程**，故零新增 cron/脚本）：每个自然日首次运行写一行到 `work/.storage_history.jsonl`（当日幂等、保留 180 天），字段 `date / trs_bytes（只统计 trs 工作区）/ local_files / local_bytes / r2_objects / r2_bytes / presign`；**R2 读不到时 `r2_*` 写 `None`（不写 0）**，前端对该点**断线**（防假跌）
- **下载签发计数**：`/api/download` 每次签发成功 `settings.bump_presign()` +1（落 `work/.web_stats.json`）——预签名是本地计算、不产生 R2 API 调用，这是「近似下载量」的唯一口径（R2 官方口径需 CF GraphQL Analytics Token，判定暂不需要）
- 存储页「容量趋势 · 近 30 天」：内联 SVG 双折线（trs 工作区 / R2 归档），无新依赖；无数据时提示「明天起可见」

### 性能缓存与前端懒加载（v5.10）

- **三层缓存治理「每请求固定成本」**（修复前管理员每个请求白付 ~1.18s）：
  - `auth.py` **校验结果缓存**：key=凭据指纹+Authorization 哈希；TTL 15min **滑动续期**；**只缓存成功**（失败仍走完整 bcrypt，安全属性不变）；轮换密码/换用户名 → 指纹变化自动失配
  - `render_cache.py` **渲染 LRU**：md→HTML 按 路径+mtime+size 缓存（64MB/48 条双限），文件被管线重写自动失效（mtime 变化）
  - `r2.snapshot` **30s 快照**：**详情页与书库页共用同一 local_map key**（此前两页 key 不同互相挤掉缓存，且每次打开书都触发一次 R2 全量列举）
- **前端懒加载**（`app.js`）：打开书只发 1 个请求（详情），译文/原文/对照/元数据/术语表/插图**面板首次切换才加载**；网页预览**点击加载**（不再自动拉 1.2MB+126 图）；所有 `<img>` 注入 `loading="lazy"`；对照面板用请求序号防过期响应覆盖
- **字号体系（6 级 token）**：`--fs-2xs/xs/sm/base/lg/xl`（10/12/13/15/17/21px 的 rem 值），改全站字号只动 6 个变量；字体族 `--font-display/sans/mono` 不变
- 实测：管理员请求 1185ms→4–17ms｜渲染二次 3024ms→10ms｜详情 1847ms→15ms｜打开书 ≈12s→≈0.4s（详见版本演进 v5.10、问题 #36–38）

### 边缘缓存与插图缩略图（v5.11）

- **CF 边缘缓存（P1a）**：图片/封面响应显式 `Cache-Control: public, max-age=14400`（`_IMG_CACHE`，main.py 两处）；CF Cache Rule（`trs.andrew-li.top` + `/file/images/` → Eligible，Edge/Browser TTL Respect origin）。机制要点：CF 对 .png/.jpg 本有扩展名默认缓存；**带 Authorization 的冷对象此前 BYPASS，`public` 头让其也能入库**；边缘分机房独立（验收需连测数次）
- **插图缩略图（P1b）**：`GET /api/books/{name}/thumb/{path}` —— 1600px JPEG，缓存 `work/.thumbs/`（书目录之外，mtime 失效，并发闸门 2）；原图 ≤1600px 或生成后 ≥原图 90% 时**直接供原图**；插图网格走缩略图、点击看原图。实测大图 -86.4%
- **存储列举 30s 缓存（P1-3）**：`r2.objects_all(force=False)` 默认 30s 复用（失败不缓存）；GC 删前复核与存储页 `refresh=1` 强制刷新——安全/新鲜度优先
- **上传流式化（P2-1 + P1-2）**：1MB 分块落盘（峰值 ~1MB），95MB 上限中途提前 413，失败自动清任务目录（`jobs.discard`）

### 预览双源分发与回归套件（v5.12）

- **预览 R2 双源（P2-2，已上线）**：`preview_sync.py` 把 `book.html`（**上传前注入懒加载**）+ `images/**` 幂等同步到**独立桶**（`translate-preview`；ETag(md5)+尺寸双比对；归档桶与归档 GC 零改动；上传对象**显式携带 Content-Type**——缺类型会让 CF 直连把 book.html 当纯文本，2026-09-20 修复 #47）。整本同步完成后写 `.preview_sync_state.json`（`complete=true` + 内容签名 `sig`）；`preview.py` 仅在「开关开 且 已同步 且 内容未再变」时把 `/file/images/` 链接重写为 `{preview_base}/books/{书}/images/…`（book.html iframe、md 渲染、插图原图三处），否则一律回退本地直连。**回滚 = 存储页「预览走 R2」开关**；新书/重译期间 pending 先降级 complete=false（防裂图）
  - **公共域**：`trspre.andrew-li.top`（R2 自定义域，最小 TLS 1.3）——iframe 直连该域的 `books/{书}/book.html`（图内相对路径天然解析到同桶）；R2 版 book.html 由同步器注入 lazy

  - **实测**：首传 394 对象 / 109.5MB @1Mbps 满速 19 分钟；冷图回源 A/B 88KB/s（经VPS）→ 254KB/s（经R2）；VPS 出网占用归零
